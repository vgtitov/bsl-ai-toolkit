# Обновление клона после 05.10.2026

5 октября 2026 года история репозитория переписана: из старых коммитов и их сообщений убраны внутренние
идентификаторы (адреса и имена, которые не должны были попасть в открытый репозиторий). **Содержимое файлов
текущей версии не изменилось** — дерево ветки `main` до и после совпадает байт в байт. Изменились только
отпечатки (SHA) коммитов.

## Что это значит для вас

| У вас | Что делать |
|---|---|
| Клон без своих правок | три команды ниже |
| Клон со своими коммитами или веткой | сохранить их отдельной веткой, перенести поверх новой `main` |
| Форк | синхронизировать `main` форка с новой историей (команды те же), ветки с правками перенести |
| Открытый запрос на изменение | перенести коммиты на новую `main` (ниже) |
| Установка, закреплённая на теге | работает как раньше; теги `v2.x` будут перевыпущены на новых коммитах, после этого нужен `git fetch --tags --force` |

## Клон без своих правок

```bash
git fetch origin
git checkout main
git reset --hard origin/main
```

Если `git status` показывает ваши незакоммиченные правки — сначала сохраните их (`git stash` или копия файлов):
`reset --hard` их сотрёт.

После перевыпуска тегов:

```bash
git fetch origin --tags --force
```

## Свои коммиты или ветка

```bash
git fetch origin
git branch backup-before-rewrite            # страховка: старое состояние остаётся в этой ветке
git checkout -b my-work-new origin/main
git cherry-pick <ваши коммиты по порядку>
```

Не сливайте (`merge`) старую ветку с новой `main` и не делайте `pull` без `--ff-only`: так старая история вернётся
в репозиторий целиком.

## Запрос на изменение, открытый до 05.10.2026

Перенесите свои коммиты на новую `main` так же, через `cherry-pick`, и обновите ветку запроса
(`git push --force-with-lease`). Запросы, основанные на старой истории, приниматься не будут.

## Проще всего

Если своих правок нет — удалите каталог и склонируйте заново.
