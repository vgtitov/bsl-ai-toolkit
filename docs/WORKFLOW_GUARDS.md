# Ponytail, лестница решения, дисциплина и второе мнение

Вспомогательные механизмы вокруг агента. Ставятся онбордингом и обновлением, каждый отключается флагом. Основа набора (поиск по коду, BSL LS, правки метаданных, эксплуатация) описана в [README](../README.md).

## Ponytail и правило «сначала проверь, что уже есть»

- **[Ponytail](https://github.com/DietrichGebert/ponytail)** (MIT, автор Dietrich Gebert) — плагин для Claude Code и
  Codex: перед написанием кода агент проходит лестницу «нужно ли это вообще → есть ли уже готовое → минимум кода».
  Ставится установщиком вместе с остальными компонентами, на пользователя (действует во всех его проектах).
- **Правило** в `core/AGENTS.md` (блок `check-existing-first`): та же лестница под 1С: типовая и БСП → общие модули проекта → механизмы платформы → одна строка → минимум. Для аналитика:
  есть ли уже типовое решение или существующий отчёт, прежде чем ставить задачу на новое.
- **Ponytail касается только кода, при любой роли.** Постановки, требования, паспорта задач, ТЗ, схемы, протоколы,
  тест-кейсы и обязательные комментарии не сокращаются: их полноту задаёт стандарт команды. Это сказано в правиле
  и в скиллах аналитика и тестировщика. Валидацию, права и защиту данных правило не упрощает.

Режим по профилю `ONEC_ACTIVE_PROFILE` (его задаёт командный онбординг): `analyst` → `off`, остальные и без профиля → `lite`.
```bash
bash onboard/onboard.sh                       # Ponytail ставится вместе с остальным
bash onboard/onboard.sh --ponytail-mode full   # режим явно (одиночная работа)
bash onboard/onboard.sh --no-ponytail          # без плагина
```
```powershell
.\onboard\onboard.ps1 -PonytailMode full
.\onboard\onboard.ps1 -NoPonytail
```
`scripts/update.sh` / `update.ps1` тоже ставят Ponytail (кроме тех, кто выключил его руками); пропустить: `AI_TOOLKIT_NO_PONYTAIL=1`.

Повторный запуск безопасен: плагин ставится штатными `claude plugin` / `codex plugin`, чужие настройки не
трогаются. Режим пишется в `~/.config/ponytail/config.json`, только если его там ещё нет; сменить потом —
`/ponytail default <режим>` в агенте. После установки в Codex один раз открой `/hooks` и разреши два хука Ponytail;
для хуков нужен `node`.

Выключить насовсем (установщик и обновление уважают): `claude plugin disable ponytail@ponytail`; в Codex —
`enabled = false` в `[plugins."ponytail@ponytail"]` файла `~/.codex/config.toml`; или `/ponytail default off`.

## Минимально достаточное решение (аналитик и архитектор)

Аналог Ponytail для анализа и проектирования: прежде чем предложить доработку, агент проходит лестницу
«проблема есть → без разработки → типовая и БСП → доработки проекта → минимальная доработка → новое» и
записывает в документе, на какой ступени остановился. Сокращает решение, а не документ: разделы ЧТЗ,
паспорта и критерии приёмки пишутся полностью. Скилл `1c-analyst`, `references/solution-ladder.md`.

## Дисциплина выполнения

Stop-хук `scripts/discipline_gate.py` не даёт закончить ход «на словах»: код изменён без проверки (тесты, BSL LS,
смоук, линтер), ход кончается обещанием без действия, «готово» в не-код задаче без файла и источников.
Смотрит только текущий ход. Ставится установщиком и обновлением в `~/.claude/settings.json`, работает во всех
проектах. Режим — `AI_TOOLKIT_DISCIPLINE`: `warn` по умолчанию (предупреждение), `enforce` (вернуть модель
доделывать), `off`. Не ставить: `--no-discipline` / `-NoDiscipline` при онбординге, `AI_TOOLKIT_NO_DISCIPLINE=1` при обновлении.
Выключить насовсем: `"env": {"AI_TOOLKIT_DISCIPLINE": "off"}` в своих настройках, установщик его не перебивает.
Убрать хук: `python scripts/discipline_gate.py uninstall`.

## Второе мнение: Codex, Copilot, модель без обучения

Claude не проверяет сам себя: ревью и проверку решений выносит модель другого семейства.
`scripts/second_opinion.py review --base origin/main` или `ask "контекст и вопрос"` идёт по цепочке и
вызывает только настроенное: **Codex** (CLI и вход) → **Copilot или другой корпоративный ассистент**
(`AI_TOOLKIT_COPILOT_CMD` — команда, читающая вопрос со STDIN) → **модель без обучения** (только при
`OPENROUTER_API_KEY` и `AI_TOOLKIT_NOTRAIN=1`; только провайдеры без хранения и обучения). Бесплатные модели
не вызываются: они обучаются на запросах. Если в запросе, диффе или вложении есть e-mail или телефон, текст уходит **только доверенному корпоративному
ассистенту** (`AI_TOOLKIT_COPILOT_CMD`, например M365 Copilot) без правок; Codex и внешние модели пропускаются.
Нет такого ассистента — отказ (код 2), никому не отправляется.
Не ответил никто — код 2.

`--risk critical|normal|low` задаёт порядок: critical — Codex первым (его лимит маленький, берём на
важное), normal (по умолчанию) — корпоративный ассистент первым, Codex резервом, low — без Codex.
`ask --file путь` прикладывает файл целиком (в нём тоже не должно быть e-mail и телефонов, иначе отказ); большой
дифф `review` уходит ассистенту вложением, без нарезки. Адаптер к M365 Copilot (веб) лежит в
`scripts/copilot_adapter.py`: нужен Playwright, вход один раз; подключение через `AI_TOOLKIT_COPILOT_CMD`
(инструкция в шапке файла). Без него цепочка идёт дальше.
Окно браузера скрыто у всех в обычной работе. Оно открывается само только когда нужен человек: до первого входа и при ошибке аутентификации (сессия истекла), человек входит, вопрос повторяется скрыто. `--visible` или `AI_TOOLKIT_COPILOT_VISIBLE=1` показывает окно всегда, `AI_TOOLKIT_COPILOT_NO_LOGIN_WINDOW=1` не открывает его никогда (сервер, CI; без DISPLAY на Linux окно тоже не открывается, тогда цепочка идёт дальше).
`status` показывает, что настроено и почему нет; `status --probe` задаёт Copilot короткий вопрос на кириллице и проверяет, что вход работает и кодировка не ломает текст (на Windows вопрос и ответ идут в UTF-8 независимо от локали).

**Лимит или недоступность звена не стопорят ревью.** Звено, которое не ответило (лимит, нет входа, нет ключа,
таймаут), пропускается, цепочка идёт к следующему настроенному, повторов нет. Сообщение страницы про лимит
(`You've used your daily chat limit`, «достигли лимита» и подобное, ответ короче 500 знаков) ответом не считается ни у
одного звена, включая Codex. После лимита Copilot пишется пауза на 6 часов (`~/.cache/ai_toolkit_limit_skip/copilot`),
страницу в это время не зовём. Если не ответил никто, вывод «Второе мнение недоступно ... Готовым не считать» и строка
«Что сделать: ...» с тем, чего не хватает и как получить: Copilot `python scripts/copilot_setup.py --login`; Codex
установка (`scripts/codex_setup.py`) и `codex login`; модель без обучения переменные `OPENROUTER_API_KEY` и
`AI_TOOLKIT_NOTRAIN=1` в `.env` (ключ выпускает владелец на openrouter.ai/keys, в чат и в репозиторий его не кладут).
Та же строка выводится в `status`. Без единого настроенного звена честный вывод: «не проверено: настрой хотя бы одно».

**По умолчанию второе мнение даёт M365 Copilot** (лимитов у всех много, данные уже в корпоративном контуре):
онбординг и обновление проверяют Microsoft Edge, через который работает адаптер (`scripts/copilot_setup.py`), вход в M365 делается один раз
(`python scripts/copilot_setup.py --login`, откроется окно). Codex — для продвинутого (`--risk critical`) и
резервом. Не ставить: `--no-copilot` / `-NoCopilot`, `AI_TOOLKIT_NO_COPILOT=1` при обновлении.

Codex ставится онбордингом и обновлением (`scripts/codex_setup.py`: официальный плагин
[openai/codex-plugin-cc](https://github.com/openai/codex-plugin-cc) и CLI через npm). Подходит любой план
ChatGPT, включая бесплатный: вход один раз `codex login`. Для рабочего кода выключи обучение:
ChatGPT → Settings → Data Controls → Improve the model for everyone → Off. OpenAI не работает в части стран
(в том числе РФ и РБ): `codex_setup.py --check` отличает геоблок от сбоя сети, нужен корпоративный VPN.
Не ставить: `--no-codex` / `-NoCodex`, `AI_TOOLKIT_NO_CODEX=1` при обновлении.
`uninstall`/`remove` не годятся: следующее обновление поставит плагин снова. На время сессии — `stop ponytail`.
