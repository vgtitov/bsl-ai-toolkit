# Рабочее место разработчика 1С на 1C:EDT

Только то, что специфично для 1С/EDT и на чём реально спотыкаются. Установка git, Java и прочие общие
шаги здесь не пересказываются. MCP-плагин EDT — `EDT_SETUP.md`, git-хуки и гейт метаданных — `git.md`.

## Каталоги

Один корень разработчика, внутри — `db` (локальные базы), `ws` (рабочие области EDT), `rp` (клоны
репозиториев), `cf` (`.cf`/`.cfe`), `tmp` (кэш IDE, логи, heap dump), `bk` (копии). Важно: репозиторий
не внутри `ws`, рабочая область не внутри `rp` — иначе git видит служебные файлы IDE, а IDE
пересобирает проект при каждом переключении веток.

## Версии

Платформа нужной версии под каждый контур: если контуры на разных версиях, ставятся обе — они
уживаются. Версия EDT должна быть совместима с платформой (таблица у вендора), версия Java — с EDT.

## Память IDE — главный параметр

Параметры JVM задаются **один раз в 1C:EDT Start** у установленной версии среды, не в проекте: проекты
берут их оттуда. Запуск ярлыком конкретной версии эти параметры игнорирует — IDE работает на умолчаниях
и тормозит. Дубли строк (`-Xmx` дважды) приводят к тому, что применяется не то значение.

```
-Djava.io.tmpdir=<корень>/tmp/
-Xms4G
-Xmx14G            # при 32 ГБ ОЗУ; при 16 ГБ — меньше
-Xss1M
-XX:MetaspaceSize=512M
-XX:MaxMetaspaceSize=1G
-XX:ReservedCodeCacheSize=256M
-XX:+UseG1GC
-XX:MaxGCPauseMillis=200
```

Полезно включить индикатор кучи в строке состояния — видно, когда памяти не хватает, а не гадать.

## Параметры рабочей области

- **снимки метаданных** для веток (`main`, `develop`, `feature/*`, `hotfix/*`) — без них переключение
  ветки перечитывает проект целиком;
- каталоги по умолчанию: информационные базы → `db`, git → `rp`, проекты → `ws`.

## Два проекта: типовая и расширение

Разработка идёт в расширении, но EDT (и агент) нуждаются в локальной копии базовой конфигурации, иначе
расширение целиком в ошибках «неизвестный тип». Порядок: склонировать оба репозитория, импортировать
оба проекта, в свойствах расширения указать базовую конфигурацию. Типовую не менять и не коммитить —
она словарь, а не рабочий проект.

## Лицензия для локальной базы

Без лицензии файловая база не открывается («не найден ключ защиты»). Разработчику подходит персональная
community-лицензия вендора: регистрация на сайте разработчиков, токен, активация при первом запуске.
Учётная запись личная, не общая корпоративная — иначе активации конфликтуют.

## Антивирус и длинные пути

EDT и платформа создают тысячи мелких файлов: без исключений антивирус даёт постоянную загрузку CPU и
портит кэш проекта. Исключения согласуются со службой безопасности. Длинные пути обязательны:
`git config --system core.longpaths true` — иначе часть файлов конфигурации не выгружается.

## Готовность рабочего места

- [ ] версии платформы / EDT / Java совместимы, `JAVA_HOME` указывает на нужную JDK;
- [ ] параметры JVM заданы в EDT Start, без дублей; IDE запускается через EDT Start;
- [ ] каталоги `db`/`ws`/`rp`/`cf`/`tmp` созданы, пути IDE указывают на них;
- [ ] `core.longpaths` включён, `git lfs install` выполнен, если проект использует LFS;
- [ ] проект расширения связан с базовой конфигурацией, ошибок «неизвестный тип» нет;
- [ ] локальная база создана в `db` и обновляется из проекта;
- [ ] git-хуки поставлены (`scripts/install_git_hooks.py`) — вместе с ними гейт метаданных.
