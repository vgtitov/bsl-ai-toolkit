# Рабочее место разработчика 1С на 1C:EDT

Что должно быть установлено и настроено, чтобы команда могла разрабатывать в 1C:EDT с хранением
исходников в git. Порядок проверен на переходе команды с Конфигуратора и хранилища конфигураций;
пункты, на которых люди спотыкались, помечены как грабли.

Про MCP-плагин EDT (живой доступ агента к рабочему пространству) — отдельный документ `EDT_SETUP.md`.
Про git-хуки, идентичность и токены — `git.md`.

## Структура рабочих каталогов

Один корневой каталог разработчика на диске с запасом места, внутри — строгое разделение:

| Каталог | Что внутри |
|---|---|
| `db` | локальные файловые базы |
| `ws` | рабочие области (workspace) EDT |
| `rp` | клоны git-репозиториев |
| `bk` | резервные копии |
| `cf` | файлы конфигураций `.cf` / `.cfe` |
| `tmp` | временные файлы, кэш IDE, логи, heap dump |

Правила: репозиторий не лежит внутри `ws`, рабочая область не лежит внутри `rp`, на каждый проект —
свой каталог. Локальные базы, кэши и резервные копии источником истины не являются: истина — git.

## Что ставим

1. **Платформа 1С** нужной версии (64-разрядная, от администратора). Если контуров несколько и версии
   платформы у них разные — ставим все нужные, они уживаются.
2. **1C:EDT** версии, совместимой с платформой (таблицу совместимости смотреть у вендора).
3. **Java** — сборка, которую требует ваша версия EDT (обычно Azul Zulu 17 JDK FX), **установщиком**,
   с включённой опцией «Set JAVA_HOME variable».
4. **Git** и **Git LFS** (`git lfs install` один раз на машине).
5. Длинные пути: `git config --system core.longpaths true` (консоль от администратора).

### Грабли установки

- Установщик платформы запускают без прав администратора → «недостаточно полномочий», каталога версии
  в `Program Files` нет. Ставить от администратора и проверять результат, а не рапорт установщика.
- Качают `.zip` Java вместо установщика → `JAVA_HOME` не появляется, EDT не стартует.
- Установочный набор запускают из облачной папки с пробелами и кириллицей в пути → скрипты падают.
  Копировать локально, в путь без пробелов.
- Прокси/VPN-клиент блокирует клиент облачного хранилища, из которого берут дистрибутивы и инструкции.

## Настройка EDT

### Параметры JVM — один раз на версию среды

Задаются в **1C:EDT Start** у установленной версии среды, а не в свойствах проекта: проекты
подтягивают их сами. Типовой набор (значения памяти — под объём ОЗУ машины):

```
-Djava.io.tmpdir=<корневой каталог>/tmp/
-Xms4G
-Xmx14G            # при 32 ГБ ОЗУ; при 16 ГБ — заметно меньше
-Xss1M
-XX:MetaspaceSize=512M
-XX:MaxMetaspaceSize=1G
-XX:ReservedCodeCacheSize=256M
-XX:+UseG1GC
-XX:MaxGCPauseMillis=200
```

Грабли: дубли параметров (`-Xmx` дважды) — IDE запускается не с теми значениями; запуск ярлыком
конкретной версии вместо EDT Start — параметры не применяются вовсе.

### Остальное в параметрах рабочей области

- показывать состояние кучи в строке состояния — видно, когда памяти не хватает;
- включить **снимки метаданных** для веток (`main`, `develop`, `feature/*`, `hotfix/*`) — это то, что
  делает переключение веток быстрым;
- каталог информационных баз по умолчанию — ваш `db`;
- каталог git по умолчанию — ваш `rp`;
- путь к проектам — ваш `ws`.

### Два проекта: типовая конфигурация и расширение

Разработка идёт в расширении, но EDT и агенту нужна локальная копия базовой конфигурации: без неё
расширение показывает ошибки «неизвестный тип».

1. Клонировать оба репозитория в `rp`.
2. Импортировать оба проекта в рабочую область.
3. В свойствах проекта расширения → **Расширение конфигурации → Базовая конфигурация** указать проект
   типовой.
4. Базовую конфигурацию не менять, не коммитить, веток в ней не создавать — она только «словарь».

### Лицензия платформы

Для локальной файловой базы нужна лицензия, иначе база не открывается («не найден ключ защиты»).
Разработчику подходит персональная community-лицензия вендора: регистрация на сайте разработчиков,
получение токена, активация при первом запуске. Учётная запись — личная, не общая корпоративная.

### Антивирус

IDE и платформа создают тысячи мелких файлов: без исключений антивирус даёт 100% CPU, ломает кэш
проекта и блокирует временные файлы. Исключения согласуются со службой безопасности — самостоятельно
их не добавляют.

## Проверка готовности

- [ ] нужные версии платформы, EDT и Java установлены;
- [ ] `JAVA_HOME` указывает на нужную JDK;
- [ ] параметры JVM заданы в EDT Start, без дублей;
- [ ] git установлен, `user.name` и `user.email` заданы, `core.longpaths` включён;
- [ ] `git lfs install` выполнен (если проект использует LFS);
- [ ] созданы каталоги `db`, `ws`, `rp`, `bk`, `cf`, `tmp`; пути IDE указывают на них;
- [ ] доступ к git-платформе получен, репозиторий склонирован в `rp`;
- [ ] проект открывается, расширение связано с базовой конфигурацией, ошибок «неизвестный тип» нет;
- [ ] локальная база создана в `db` и обновляется из проекта;
- [ ] git-хуки поставлены (`scripts/install_git_hooks.py`) — в том числе гейт метаданных;
- [ ] разработчик умеет: создать ветку под задачу, зафиксировать, отправить, открыть merge request.

Пока хотя бы один пункт не выполнен, рабочее место к командной разработке не готово.
