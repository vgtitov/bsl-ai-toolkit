# Режим наставника: off, ask, on

Наставник (`ai-mentor`) включается параметром и в выключенном виде ничего не стоит. Выбор человека лежит в его личном файле вне репозитория и соблюдается между сессиями.

## Состояние
Файл `~/.ai-mentor.json` (путь можно сменить переменной `AI_MENTOR_STATE`). Один для всех агентов.

| Поле | Смысл |
|---|---|
| `mode` | `off` не предлагать и не грузить, `ask` (по умолчанию) можно предложить один раз, `on` наставник работает |
| `declined_at` | дата отказа |
| `remind_after` | «позже»: до этой даты не предлагать |
| `offers_made`, `last_offer` | сколько предложений было и когда последнее; пауза между предложениями 14 дней |
| `level_card` | путь к карточке уровня, по умолчанию `~/.ai-mentor-card.md` |

Команды человека (агент выполняет через `scripts/mentor.py` и отвечает одной фразой): «включи ментора», «выключи» и «не предлагай», «напомни через месяц», «покажи, что ты про меня хранишь», «сбрось». Или вручную: `/ai-mentor on|off|ask|status|reset`. В режиме `off` в контексте нет ничего о наставнике (это и есть нулевая цена), поэтому включение словами «включи ментора» там не гарантировано: надёжно работает `/ai-mentor on`. Повреждённый файл состояния считается отказом (`off`), чтобы не предлагать наставника человеку, который мог отказаться.

## Как устроена цена
1. Скилл помечен `disable-model-invocation: true`: по документации Claude Code его описание не попадает в контекст вообще, тело и справочники грузятся только при вызове.
2. Хук SessionStart (`mentor.py hook`) читает файл. В `off` он печатает 0 строк. В `ask` одну короткую строку, пока предложение возможно (после ответа или в паузе молчит). В `on` одну строку «прочитай SKILL.md».
3. Тело (12 КБ) и справочники читаются агентом только в `on` или после согласия.

Замер (`claude -p`, haiku, `--setting-sources project`, чистое дерево git, сумма входных токенов; разброс от git status и имён коммитов примерно ±60):

| Вариант | Токенов на старте | Разница к «без ai-mentor» |
|---|---|---|
| Без ai-mentor (80c7492 без папки скилла) | 55298 | 0 |
| v1 (описание 983 знака в контексте у всех) | 55573 | +275 |
| v2, режим `off` | 55241 | в пределах шума (-57) |
| v2, режим `ask` (строка хука) | 55255 | +14 (в других формулировках строки до +65) |
| v2, режим `on` (строка хука) | 55244 | +3 (шум; строка около 20 токенов) |

Цель «не больше 25 токенов в `off` и `ask`» выполнена в `off` и в последнем замере `ask`. Точнее замер не удаётся, потому что в системный промпт попадают имя ветки и последние коммиты.

## Когда наставник предлагает себя
Только в режиме `ask`, один раз за сессию, после результата, не вместо него. Сигналы: слабая постановка три раза подряд, текст Jira или Confluence вставлен вручную без настроенного API, одна и та же ошибка дважды, вопрос «как лучше спросить». Не предлагает, когда человек торопится или просит «просто сделай». Фразы и порядок: `core/skills/ai-mentor/OFFER.md`. Предложение подключить Jira и Confluence по API отдельное и тоже одно: токен только на чтение, кладёт человек сам через `scripts/set_secret.py`, в чат не вставляет.

Что нет без хука: агент не знает режим, пока не прочитает файл, поэтому блок правил начинается с «прочитай `~/.ai-mentor.json`». Блок ставится по желанию, без него агент о наставнике не знает и ничего не предлагает.
