# Режим наставника: off, ask, on

Наставник (`ai-mentor`) включается параметром и в выключенном виде ничего не стоит. Выбор человека лежит в его личном файле вне репозитория и соблюдается между сессиями.

## Состояние
Файл `~/.ai-mentor.json` (путь можно сменить переменной `AI_MENTOR_STATE`). Один для всех агентов.

| Поле | Смысл |
|---|---|
| `mode` | `off` по умолчанию: не предлагать и не грузить; `ask` можно предложить один раз, `on` наставник работает. Нет файла означает `off` |
| `schema` | формат записи; файл другого формата или без поля читается как `off`, обновление набора наставника не включает |
| `declined_at` | дата отказа |
| `remind_after` | «позже»: до этой даты не предлагать |
| `offers_made`, `last_offer` | сколько предложений было и когда последнее; пауза между предложениями 14 дней |
| `level_card` | путь к карточке уровня, по умолчанию `~/.ai-mentor-card.md` |

Включает наставника только явная команда: `/ai-mentor on` или `/ai-mentor ask`, либо ответ «да» на один вопрос: он задаётся при первой установке (`onboard/onboard.*`) и при обновлении до версии с наставником (`scripts/update.*`), по одному разу на человека (`mentor.py onboarding`, поле `onboarding_asked`); молчание оставляет `off` и вопрос повторится при следующем обновлении, ответ «нет» закрывает его насовсем. Словами и хуком он сам не включается, обновление набора выбор не меняет. Остальные команды: `/ai-mentor off|status|reset`, а когда наставник включён, ещё «выключи» и «не предлагай», «напомни через месяц», «покажи, что ты про меня хранишь», «сбрось». В `off` в контексте нет ничего о наставнике (это и есть нулевая цена). Повреждённый файл состояния считается отказом (`off`), чтобы не предлагать наставника человеку, который мог отказаться.

## Как устроена цена
1. Скилл помечен `disable-model-invocation: true`: по документации Claude Code его описание не попадает в контекст вообще, тело и справочники грузятся только при вызове.
2. Хук SessionStart (`mentor.py hook`) читает файл. В `off` он печатает 0 строк. В `ask` одну короткую строку, пока предложение возможно (после ответа или в паузе молчит). В `on` одну строку «прочитай SKILL.md».
3. Тело (12 КБ) и справочники читаются агентом только в `on` или после согласия.

Замер (`claude -p`, haiku, `--setting-sources project`, чистое дерево git, сумма входных токенов; разброс от git status и имён коммитов примерно ±60):

| Вариант | Токенов на старте | Разница к «без ai-mentor» |
|---|---|---|
| Без ai-mentor (80c7492 без папки скилла) | 55298 | 0 |
| v1 (описание 983 знака в контексте у всех) | 55573 | +275 |
| v2, режим `off` | 55241 | в пределах шума (-57) |
| v2, режим `ask` (строка хука) | 55255 | +14 (в других формулировках строки до +65) |
| v2, режим `on` (строка хука) | 55244 | +3 (шум; строка около 20 токенов) |

Цель «не больше 25 токенов в `off` и `ask`» выполнена в `off` и в последнем замере `ask`. Точнее замер не удаётся, потому что в системный промпт попадают имя ветки и последние коммиты.

## Когда наставник предлагает себя
Только в режиме `ask`, один раз за сессию, после результата, не вместо него. Сигналы: слабая постановка три раза подряд, текст Jira или Confluence вставлен вручную без настроенного API, одна и та же ошибка дважды, вопрос «как лучше спросить». Не предлагает, когда человек торопится или просит «просто сделай». Фразы и порядок: `core/skills/ai-mentor/OFFER.md`. Предложение подключить Jira и Confluence по API отдельное и тоже одно: токен только на чтение, кладёт человек сам через `scripts/set_secret.py`, в чат не вставляет.

## Наставник и другие агенты
Один скилл `ai-mentor` с обычным `SKILL.md`, отдельных версий под агентов нет. По документации агентов на 03.11.2026 (вживую проверен только Claude Code; Codex не отвечает из-за лимита, Cursor и VS Code на проверяющей машине не установлены):

| Агент | Читает SKILL.md | Папки проекта | Как отключить описание в контексте | Хук SessionStart |
|---|---|---|---|---|
| Claude Code | да | `.claude/skills` | `disable-model-invocation: true` | да, `.claude/settings.json` |
| Codex | да | `.agents/skills` (от текущей папки вверх до корня репо); `.claude/skills` не читает | поля нет; `agents/openai.yaml` с `allow_implicit_invocation: false` (файл лежит в скилле) | да, но другие файлы (`.codex/hooks.json`) и подтверждение через `/hooks`; хук набора для Codex не написан |
| Copilot в VS Code | да | `.github/skills`, `.claude/skills`, `.agents/skills` | то же `disable-model-invocation` | да, читает и `.claude/settings.json` (Preview) |
| Cursor | да | `.cursor/skills`, `.agents/skills`, `.claude/skills` | то же `disable-model-invocation` | да, читает и хуки Claude Code |
| Gemini CLI | не проверено | `GEMINI.md` из `AGENTS.md` | | |
| Веб-Copilot | нет файлов и хуков | | | выбор хранит человек, веб-версия вынесена в отдельный материал |

Раскладка. `sh build.sh claude` кладёт скиллы в `.claude/skills` (Claude Code, Copilot, Cursor их читают). Для Codex добавлена цель `sh build.sh agents` (на Windows `build.ps1 agents`): копия в `.agents/skills`, в git не попадает. В общую цель `all` она не входит: Copilot и Cursor читают обе папки, и две копии одних скиллов могли бы дважды занять контекст (как агенты склеивают одинаковые имена, документация не говорит).

Без хука (Codex пока) агент не знает режим, пока не прочитает файл. Для него и для агентов без скиллов есть блок правил `core/mentor/agent-rules.md` на 6 пунктов: он начинается с «прочитай `~/.ai-mentor.json`» и ставится по желанию в AGENTS.md. Вживую проверено: Codex с этим блоком в AGENTS.md в `off` ничего не говорит о наставнике, в `ask` предлагает один раз.

Подробности прогонов и таблица A/B: `modes-check.md`.
