# API управляемой формы: поведение, которое ловится только рантаймом

Факты платформы 8.3, проверенные на реальных падениях, а не по справке. Все они объединены одним:
код выглядит правильным и компилируется, а ведёт себя не так, как ожидает разработчик.

## Обход элементов формы

**Плоского обхода нет.** `Форма.Элементы` (тип `ВсеЭлементыФормы`): `Количество()` считает ВСЕ
элементы вне зависимости от иерархии, но обращение по индексу в этом диапазоне **падает** —
«Получение элемента по индексу для значения не определено». То есть цикл
`Для Индекс = 0 По Элементы.Количество() - 1 Цикл Элементы[Индекс]` работать не будет.

Как обходить правильно:
- по имени — `Форма.Элементы.Найти("Имя")` работает для элемента любой вложенности;
- дети группы или таблицы — `Группа.ПодчиненныеЭлементы` в цикле `Для Каждого`.

## Команды: имя, тайминг, перехват

**У кнопок команд командного интерфейса свойство `ИмяКоманды` пустое.** Скрывать такие кнопки можно
только по имени самой кнопки; имя детерминировано (`Форма` + путь команды без точек) и не зависит от
конкретной формы.

**Тайминг.** Команды командного интерфейса платформа перепоказывает ПОСЛЕ `ПриСозданииНаСервере`,
затирая серверное скрытие. Фильтровать их надо в обработчике обновления команд
(`ПодключаемыеКомандыКлиентСервер.ОбновитьКоманды` и его расширения). Команды самой ФОРМЫ, наоборот,
спокойно скрываются в `ПриСозданииНаСервере` и не затираются.

**Команда формы расширением не перехватывается.** Ни `&Перед`/`&После`/`&Вместо` на имя
процедуры-обработчика команды, ни `callType` при программном создании: платформа отвечает
«Call-type interception is not supported for a form command action; callType applies to a form ITEM
event». Хуже того, аннотация на имя команды **создаётся без ошибки** (проверка проекта чиста) и просто
никогда не срабатывает — молча. Перехватывать нужно обычный метод, который команда вызывает внутри
себя: он перехватывается штатно.

## Параметры формы живут только в вызове создания

`Параметры` гарантированно доступны в `ПриСозданииНаСервере` и во всём, что вызвано синхронно из этой
же цепочки (включая методы, к которым расширение добавило `&После`). В ПОЗДНЕЙШЕМ отдельном серверном
вызове — типичный случай, клик по команде формы, который делает новый круг вызова сервера, —
`Параметры.Свойство("Имя", Значение)` надёжно возвращает `Ложь`, **без исключения**: тип объекта тот же,
никакого сигнала о проблеме нет.

Именно поэтому типовой код никогда не читает `Параметры` вне создания формы: нужные значения один раз
копируются в реквизиты формы и дальше читаются оттуда. **Правило: нужен параметр открытия где-то кроме
цепочки создания — заведите реквизит формы и скопируйте значение однократно.**

Диагностировать это надо явным булевым результатом (`Результат = Параметры.Свойство(...)`), а не
выводом значения: значение по умолчанию `Ложь` маскирует «ключ не найден» под «ключ равен лжи».

## Заимствованная типовая форма в расширении

**Секция реквизитов должна быть пустой**, кроме реально добавленных расширением. Копии реквизитов
поставщика (идентификаторы от 1000001) EDT считает собственными реквизитами расширения, и их типы
обязаны разрешаться внутри расширения. Ссылки на незаимствованные объекты конфигурации не
резолвятся, EDT пишет битый `Type` в выгрузку формы, и обновление ИБ падает с «Исключение XDTO …
Несоответствие свойства и элемента данных XDTO: Свойство: 'Type'» (у другого разработчика тот же
корень проявился как полуторачасовое зависание обновления).

Диагностика — проверка проекта с `checkId: form-legacy-check-type-description-types`: ошибки
«Неизвестный тип» ровно по незаимствованным типам. Норма для заимствованной формы — ноль собственных
реквизитов. Лечение — удалить лишние реквизиты формы расширения: элементы и их пути к данным не
пострадают, они резолвятся на реквизиты поставщика.

**Настройки динамического списка лежат не в файле формы.** В формате EDT отбор, порядок, условное
оформление и режимы полей хранятся в отдельном файле
`<Объект>/Forms/<Форма>/Attributes/<Реквизит>/ExtInfo/ListSettings.dcss`. При переносе формы
копированием этот подкаталог теряют, и в рантайме «Ещё → Настроить список» отвечает «Не предусмотрено
возможности настройки для этого списка» — при том что сам файл формы побайтно совпадает с рабочим
образцом. Лечение: создать `.dcss` по образцу рабочей формы (пустые отбор/порядок/оформление со своими
идентификаторами), затем Refresh (F5) проекта.
