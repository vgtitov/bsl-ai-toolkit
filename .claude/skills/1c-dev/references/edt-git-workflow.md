# EDT + git: что отличается от общей практики

Только специфика 1С и EDT. Общие вещи про git (ветки, merge request, секреты не в репозитории) здесь
не пересказываются. Ловушки инструмента — `1c-metadata/references/edt-mcp-known-issues.md`,
рабочее место — `docs/edt-workstation.md`.

## Смена модели: ветка вместо захвата объекта

В хранилище конфигураций объект **захватывают**, и пока он захвачен, другие его не правят. В git
блокировок нет: каждый работает в своей ветке, расхождения сводятся при слиянии. Для команды, пришедшей
из хранилища, это главная перестройка — и источник первых ошибок: правки по привычке делают в общей
ветке, как раньше в единственном хранилище.

EDT сравнивает объекты **по свойствам**, а не текстом: две правки разных свойств одного объекта
сливаются автоматически, тогда как в Конфигураторе такую ситуацию приходилось разруливать руками.

## Специфика EDT при работе с ветками

- **Ветку создавать только пунктом «Создать ветку»** (Навигатор → Групповая разработка). Похожий путь
  «Переключиться на → создать» оставляет ветку без связей, которые потом настраивать вручную.
- **При создании ветки EDT спрашивает про информационную базу.** Если локальные копии баз не
  используются (базы большие) — «не использовать», иначе IDE создаёт копию базы на каждую ветку.
- **Незафиксированные изменения при создании ветки** EDT предлагает зафиксировать, спрятать или
  отклонить — это и есть момент, когда обнаруживается, что правки ушли не в ту ветку.
- **Снимки метаданных** (параметры рабочей области) — то, что делает переключение веток быстрым;
  без них каждое переключение перечитывает проект целиком.
- **Проект расширения связывается с базовой конфигурацией** (свойства проекта → Расширение
  конфигурации). Без этого весь проект в ошибках «неизвестный тип», и это не поломка репозитория.
- **Версия платформы живёт в проекте.** После обновления IDE или платформы проект остаётся на старой
  версии и даёт «ошибка взаимодействия с платформой» — поднимается в свойствах проекта.

## Перед push: гейт метаданных

`.mdo` и `.rights` IDE переписывает целиком из модели в памяти. Если модель старее ветки, на диск
уходит устаревшее состояние: git видит обычную правку, конфликта нет, слияние проходит зелёным, объект
исчезает молча. В истории пути (`git log -- <файл>`) такая потеря не видна — слияние, совпавшее с одним
из родителей, из неё выпадает.

Поэтому вместе с git-хуками ставится `scripts/check_metadata_regression.py`: перед push сравнивает
`.mdo`/`.rights` с базовой веткой и блокирует отправку, если объект, реквизит, форма или право пропали,
либо у права тихо изменилось значение. Включается только в репозиториях с исходниками EDT.
Настройки и режимы — `docs/git.md`.
