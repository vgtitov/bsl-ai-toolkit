# История оценок и калибровка

Оценка без обратной связи не улучшается. Файл истории хранит пары «оценка без ИИ и факт»,
скрипт `scripts/estimate_calibration.py` превращает их в коэффициент с интервалом. Сам файл и
стартовые коэффициенты ведёт организация (в Toolkit цифр нет).

## Файл `estimate_history.csv` (UTF-8, по строке на задачу и роль)

| Поле | Смысл |
|---|---|
| `task` | ключ задачи |
| `size` | класс по размеру (по шкале локализации) |
| `work_type` | форма, отчёт, логика, интеграция, обмен, права, данные |
| `role` | аналитик или разработчик; тех-лид, архитектор, поддержка вне плана |
| `est_without_ai` | оценка без ИИ, часы, первая зафиксированная до начала работ |
| `est_date` | дата фиксации и версия базы оценки |
| `fact` | часы по роли, включая клоны и подзадачи |
| `fact_complete` | да, если списания по роли полные |
| `scope_changed` | да, если объём менялся после оценки |
| `out_of_plan` | да, если в оценку входили работы вне плана (тех-лид, архитектор, поддержка) |
| `close_reason` | выполнена, перенесена, отменена |
| `ai_stages`, `review_h` | где работал ИИ (тех-проект, код, тесты, разбор) и часы проверки человеком |
| `closed_date`, `source` | дата закрытия, откуда взяты числа |

## Что идёт в расчёт
Только `close_reason = выполнена`, объём не менялся, работ вне плана нет, списания полные, факт
больше нуля, одна (первая) оценка на задачу и роль. Остальное считается отдельным показателем
качества данных, скрипт его печатает. Оценка ровно 1 ч помечается как возможная заглушка.

## Ловушки учёта (сверено с Jira, 02.11.2026)
- Часы разработчика часто списаны на клон задачи в другом проекте, часы аналитика на исходную.
  Факт по одной из них при оценке «аналитик плюс разработчик» занижает отношение. Суммируй по клонам.
- Задача, перенесённая из прошлого месяца, имеет оценку остатка и факт всей работы. Не в расчёт.
- Клон ещё не закрыт: факт неполный, пара не в расчёт.

## Как использовать коэффициент
`python scripts/estimate_calibration.py estimate_history.csv --size M --role dev --type форма`
печатает коэффициент, 80% интервал, интервал для следующей задачи и P80, источник и статус:
«по истории, n=…», «предварительный из настроек» (`--prior`), «по умолчанию 1». Для рискованных
типов (интеграция, обмен, права) при n меньше 5 коэффициент 1; повышенный минимум задаёт
организация через `--risky-min`. Границы 0,3–1,5 только страховка. Цели разные: типичная задача
это коэффициент, ёмкость месяца это `--capacity` (сумма факта к сумме оценок, оптимистично, пока
не учтены незакрытые затянувшиеся задачи), риск срыва это P80.

Коэффициент заменяет множитель готовности только как поправка к базе без ИИ; эффект ИИ считается
после калибровки базы и по этапам, где ИИ работал.
