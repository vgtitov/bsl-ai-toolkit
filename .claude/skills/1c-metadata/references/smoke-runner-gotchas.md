# Смоук-сценарии на встроенном языке: ограничения и грабли

Обезличенный конспект боевых ошибок. Смоук-раннер выполняет сценарий через `Выполнить(ТекстСценария)`
в контексте формы внешней обработки. Отсюда набор ограничений, на которые легко наступить и потерять
по прогону на каждой (прогон занимает минуты — цена ошибки высокая).

## 1. Нельзя объявлять процедуры и функции

`Выполнить()` принимает **фрагмент операторов**, а не модуль. Любое `Функция …` / `Процедура …`
даёт `Ожидается последовательность операторов` и падает ещё до выполнения.

Писать всё инлайном. Повторяющийся код — разворачивать циклом по массиву входных значений,
результаты складывать в массив, а не выносить в функцию.

```bsl
// вместо функции с параметром — цикл по коллекции
Схемы = Новый Массив; Схемы.Добавить(СхемаА); Схемы.Добавить(СхемаБ);
Результаты = Новый Массив;
Для Каждого Схема Из Схемы Цикл
    // …тело…
    Результаты.Добавить(ТЗ);
КонецЦикла;
```

## 2. Зарезервированные слова в именах переменных

Классика, съевшая два прогона: `И`, `ИЛИ`, `НЕ`, `Для`, `Если` — не имена переменных.
`И = Пакет[4].Выбрать();` компилируется в `Неопознанный оператор`.
То же в запросе: `КАК И` даёт `Ожидается имя`. Псевдонимы таблиц — `Ид`, `Об`, `Стр`, не однобуквенные
служебные.

## 3. Поля объектов метаданных проверять ДО написания запроса

Три падения подряд были из-за запросов к незнакомым объектам «по памяти»:
несуществующее поле регистра, несуществующий метод общего модуля, неверный псевдоним.

Дешёвая привычка: перед запросом посмотреть состав измерений/ресурсов/реквизитов в XML выгрузки
(`grep -o '<Name>[^<]*</Name>'` по файлу объекта) либо через `Метаданные.…`. Это секунда против
минут прогона.

## 4. Подключение внешнего отчёта/обработки вешает пакетный сеанс

`ВнешниеОтчеты.Подключить` / `ВнешниеОбработки.Подключить` на базе, не покрытой маской
`DisableUnsafeActionProtection`, поднимает модальное окно «Защита от опасных действий».
Пакетный клиент окна не видит и **висит бесконечно** — сеансы копятся сутками и держат лицензии.

Признак: раннер молчит до таймаута, а на сервере растёт число процессов клиента с тем же
`.epf` в командной строке.

Варианты:
- проверять объект, лежащий **внутри расширения** (`Отчеты.<Имя>.Создать()`) — окна не будет;
- поднимать схему компоновки из XML: `СериализаторXDTO.ПрочитатьXML(Чтение, Тип("СхемаКомпоновкиДанных"))` —
  позволяет сравнить «до/после» без подключения внешнего файла;
- либо снять флаг у пользователя ИБ / добавить маску (см. документацию по настройке окружения).

## 5. Мутации данных — только в транзакции с откатом

Проверка, которой нужны специально созданные данные (искусственная коллизия, граничный случай),
делается так:

```bsl
НачатьТранзакцию();
Попытка
    // создать данные, выполнить замеры в переменные
Исключение
    ОтменитьТранзакцию();
    ВызватьИсключение;
КонецПопытки;
ОтменитьТранзакцию();
// затем контрольный запрос: убедиться, что мусор не остался
```

Обязателен контрольный запрос после отката — он же документирует, что база не засорена.
Учесть обязательные измерения регистра, иначе запись упадёт на проверке заполнения.

## 6. Диагностика через ложноотрицательные проверки

Реальный случай: проверка «зарегистрирован ли объект расширения» искала по **имени метаданных**,
тогда как в наименовании справочника лежит **синоним**. Результат — «не зарегистрирован» при
фактически корректной регистрации, и полчаса на ложный след.

Правило: если проверка говорит «нет», сперва убедиться, что она вообще способна сказать «да» —
поискать заведомо существующую запись тем же способом.

## 7. Полезные приёмы

- Результат компоновки в текст: `ТабДок.Записать(путь, ТипФайлаТабличногоДокумента.ANSITXT)` —
  дальше файл можно забрать и разобрать построчно вне 1С.
- Сравнение наборов данных: компоновать обе схемы **одинаковыми** настройками (детальные записи,
  один и тот же список полей), выводить через
  `ПроцессорВыводаРезультатаКомпоновкиДанныхВКоллекциюЗначений` в таблицу значений и сравнивать
  по составному ключу из всех колонок — ловит и потери, и дубли.
- Параметры отчёта, обязательные к заполнению, находить перебором
  `Настройки.ПараметрыДанных.Элементы` и подставлять первое подходящее значение из справочника.

## 8. Автоматизация веб-клиента платформы (проверено экспериментом)

Устройство страницы, выясненное разбором DOM и сетевого обмена. Пометки достоверности —
по шкале из `docs/knowledge/README.md`.

**Якоря вместо пикселей.** Элементы форм имеют детерминированные идентификаторы, куда платформа
кладёт UUID объекта — например `form<N>_Вариант_<uuid>_Подсистема_<uuid><ИмяЭлемента>`; команды
нумеруются как `cmd_<строка>_<колонка>`. Это единственный якорь, уникальный **по построению**:
имена и представления у объекта, созданного копированием, унаследованы и совпадают с оригиналом.

**Слоёная вёрстка.** Кнопка — это `<a class="press …">`, поверх неё несколько декоративных `span`
с теми же координатами. Отсюда:
- обычный клик отвергается проверкой активируемости (элемент «перекрыт») — нужен принудительный;
- правило «бери самый узкий элемент» на кнопках даёт осечку: самыми узкими оказываются украшения.
  Искать по тегу и точному тексту.
- класс кнопки по умолчанию — свойство **формы**, а не кнопки: на форме документа это будет
  «Провести и закрыть». Как якорь непригоден.

**Элементы шире содержимого.** Гиперссылка в панели — только сама надпись, а элемент растянут на
всю ширину колонки. Клик в геометрический центр попадает в пустоту справа от текста.

**Асинхронная перерисовка.** Списки достраиваются и после исчезновения индикатора загрузки:
координаты, полученные до клика, успевают устареть. Надёжнее клик по ссылке на элемент
(если инструмент это умеет), чем по координатам.

**Синтетические события мыши, отправленные на элемент, платформа игнорирует** — ввод обрабатывается
собственным механизмом. Реальный клик инструментом браузера работает.

**Язык интерфейса зависит от заголовков запроса.** Один и тот же клиент отдаёт интерфейс платформы
на разных языках, при этом данные конфигурации остаются на языке конфигурации. Привязка к строкам
интерфейса ненадёжна принципиально. Признак готовности брать структурный — например рост и
стабилизацию объёма отрисованного текста.

**Обмен с сервером** идёт POST-запросами вида `logForm?cmd=query`, `dcs?cmd=getChildFields`,
`moxel?cmd=getVisualContents`. По ним видно, дошло ли действие до сервера — это отличает
«клик не сработал» от «сработал, но результат другой».

### Дискриминатор — главное правило ступени

Признак, по которому проверяется «то ли открылось/получилось», должен **отсутствовать до действия
и появляться после**, и быть уникальным **по построению**. За одну сессию четыре подряд ложных
вывода дали признаки, которые этому не отвечали: имя варианта (унаследовано при копировании),
заголовок окна (показывает имя варианта, а не отчёта), наличие строки в тексте страницы (она есть
и в списке), отсутствие ошибки (её текст лежал скрытым шаблоном в DOM).

Надёжным оказался только состав колонок результата — то, что есть исключительно у проверяемого
объекта.
