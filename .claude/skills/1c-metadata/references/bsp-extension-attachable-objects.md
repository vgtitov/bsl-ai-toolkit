# Объект расширения, подключённый к типовым механизмам БСП

Обезличенный конспект. Закрывает частый неверный ход: агент кладёт отчёт/обработку **внутрь расширения** и
пишет в модуль объекта `СведенияОВнешнейОбработке()`, ожидая, что объект появится в интерфейсе как
дополнительный отчёт/печатная форма. Не появится. Ниже — почему и что делать вместо.

Проверено по исходному коду БСП типовой конфигурации (не по памяти); корроборировано публикациями
по внешним печатным формам на расширениях.

---

## 1. Почему `СведенияОВнешнейОбработке()` не работает для объекта расширения

`ДополнительныеОтчетыИОбработки.ПодключитьВнешнююОбработку(Ссылка)` работает только с **файлом**:
берёт двоичные данные из реквизита `ХранилищеОбработки` элемента справочника
`ДополнительныеОтчетыИОбработки`, кладёт во временное хранилище и поднимает объект через
`ВнешниеОтчеты.Создать(...)` / `ВнешниеОбработки.Создать(...)`. Объект, живущий в расширении, этим
путём не поднимается — у него нет бинарника в справочнике. Сама `СведенияОВнешнейОбработке()`
читается платформой/БСП только при регистрации файла `.erf`/`.epf`.

**Две штатные точки подмены есть, но для отчётов дырявые.** В модуле `ДополнительныеОтчетыИОбработки`:

```bsl
ИнтеграцияПодсистемБСП.ПриПодключенииВнешнейОбработки(Ссылка, СтандартнаяОбработка, Результат);
ИнтеграцияПодсистемБСП.ПриСозданииВнешнейОбработки(Ссылка, СтандартнаяОбработка, Результат);
```

Обе с флагом `СтандартнаяОбработка` — расширение может вернуть свой объект/имя. Но код открытия
ОТЧЁТА в том же модуле вызывает `ПодключитьВнешнююОбработку` и сразу `ВнешниеОтчеты.Создать(Имя)`,
минуя `ОбъектВнешнейОбработки`, то есть хук создания объекта не срабатывает. Для обработок лазейка
жизнеспособнее, для отчётов — нет. Строить на ней не стоит.

## 2. Штатный механизм: подсистема `ПодключаемыеОтчетыИОбработки`

Прямая цитата из БСП (`ВариантыОтчетовПереопределяемый.НастроитьВариантыОтчетов`):

> «В процедуре задаются только настройки отчетов (и вариантов отчетов) конфигурации.
> Для настройки отчетов из расширений конфигурации следует включать их в подсистему
> ПодключаемыеОтчетыИОбработки.»

Комментарий самой подсистемы: «Служебная переопределяемая подсистема. В состав включаются отчеты и
обработки, в модуле менеджера которых определена процедура `ПриОпределенииНастроек`.» В типовой
поставке её состав ПУСТ — это специально оставленный слот под расширения.

`ПодключаемыеКоманды` обходит состав этой подсистемы и **явно** учитывает объекты расширений
(`ОбъектМетаданныхПоставщика.РасширениеКонфигурации() <> Неопределено`), после чего вызывает
`Менеджер.ПриОпределенииНастроек(Настройки)` из модуля менеджера объекта.

### Контракт `ПриОпределенииНастроек(Настройки)`

Ключи собираются в `ПодключаемыеКоманды.НастройкиПрограммногоИнтерфейсаПодключаемыхОбъектов()`
и дополняются поставщиками (`УправлениеПечатью`, `ВариантыОтчетов`, `ЗаполнениеОбъектов`,
`СозданиеНаОсновании`):

| Ключ | Тип | Вид объекта | Что включает |
|---|---|---|---|
| `Размещение` | Массив | отчёт, обработка | к каким объектам/подсистемам подключается |
| `ДобавитьКомандыПечати` | Булево | отчёт, обработка | команда в меню «Печать» типовой формы |
| `ДобавитьКомандыОтчетов` | Булево | отчёт, обработка | команда в меню «Отчеты» формы объекта |
| `НастроитьВариантыОтчета` | Булево | только отчёт | регистрация в панели отчётов БСП |
| `ОпределитьНастройкиФормы` | Булево | только отчёт | интеграция с общей формой отчёта |
| `ДобавитьКомандыСозданияНаОсновании` | Булево | отчёт, обработка | «Создать на основании» |
| `ДобавитьКомандыЗаполнения` | Булево | отчёт, обработка | команды заполнения объекта |

Включив ключ, надо определить в том же модуле менеджера парную процедуру с тем же именем
(`ДобавитьКомандыПечати`, `ДобавитьКомандыОтчетов`, `НастроитьВариантыОтчета`, …).

## 3. Рецепт: печатная форма из расширения (в т.ч. с макетом Word)

1. Обработка в расширении; подсистема `ПодключаемыеОтчетыИОбработки` **заимствуется** в расширение,
   обработка добавляется в её состав.
2. У расширения в базе снять флажок **«Безопасный режим»** — иначе печать офисного документа
   упирается в ограничения. Это свойство ЭКЗЕМПЛЯРА расширения в ИБ, а не исходников: в дампе
   `Configuration.xml` его нет, `LoadConfigFromFiles -Extension` его не меняет. Ставится в
   Конфигураторе (Расширения конфигурации) или программно через `РасширенияКонфигурации`.
3. Макет — тип **двоичные данные**, имя с префиксом **`ПФ_DOC_`**, внутрь загружается `.docx`.
   В шаблоне: области `{v8 Область.ИмяОбласти}` … `{/v8 Область.ИмяОбласти}`, параметры `{v8 ИмяПараметра}`.
4. У обработки должна быть **основная форма** с экспортной клиентской функцией-обработчиком команды
   печати (на неё ссылается свойство `Обработчик` команды).
5. Модуль менеджера обработки — предопределённые БСП: `ПриОпределенииНастроек`,
   `ДобавитьКомандыПечати`, `Печать`, `ПолучитьДанныеПечати`; и свои: получение данных объекта,
   описание областей макета, вывод документа.
6. Типы областей офисного макета: `Общая`, `СтрокаТаблицы`, `Список`, `ВерхнийКолонтитул`,
   `НижнийКолонтитул`.

Колонки коллекции команд печати (`УправлениеПечатью`, полный список — в исходниках):
`Идентификатор`, `Представление`, `МенеджерПечати`, `ТипыОбъектовПечати`, `Обработчик`, `Порядок`,
`Картинка`, `СписокФорм`, `МестоРазмещения`, `ЗаголовокФормы`, `ФункциональныеОпции`,
`УсловияВидимости`, `ПроверкаПроведенияПередПечатью`, `СразуНаПринтер`, `ФорматСохранения`,
`ФиксированныйКомплект`, `ТребуетсяРасширениеРаботыСФайлами` и др.

Полезные функции: `УправлениеПечатью.МакетПечатнойФормы(ПутьКМакету, КодЯзыка)`,
`УправлениеПечатью.ИнициализироватьМакетОфисногоДокумента(ДвоичныеДанныеМакета, …)`.

## 4. Рецепт: отчёт из расширения в панель «Отчеты»

1. Отчёт в расширении, включён в **прикладную** подсистему (раздел, где он должен появиться) —
   это даёт размещение в командном интерфейсе.
2. Отчёт дополнительно включён в **`ПодключаемыеОтчетыИОбработки`**.
3. Модуль менеджера отчёта:

```bsl
Процедура ПриОпределенииНастроек(Настройки) Экспорт
	Настройки.НастроитьВариантыОтчета = Истина;
	Настройки.Размещение.Добавить(Метаданные.Подсистемы.Раздел.Подсистемы.Подраздел);
КонецПроцедуры

Процедура НастроитьВариантыОтчета(Настройки, НастройкиОтчета) Экспорт
	МодульВариантыОтчетов = ОбщегоНазначения.ОбщийМодуль("ВариантыОтчетов");
	НастройкиОтчета.Включен = Истина;
	НастройкиОтчета.Размещение.Вставить(Метаданные.Подсистемы.Раздел.Подсистемы.Подраздел);
	НастройкиВарианта = МодульВариантыОтчетов.ОписаниеВарианта(Настройки, НастройкиОтчета, "ИмяВарианта");
	НастройкиВарианта.Наименование = НСтр("ru = '…'");
	НастройкиВарианта.Описание     = НСтр("ru = '…'");
	НастройкиВарианта.НастройкиДляПоиска.НаименованияПолей = НСтр("ru = '…'");
КонецПроцедуры
```

`ИмяВарианта` — имя предопределённого варианта настроек СКД (`settingsVariant/name`), а не
произвольная строка.

## 5. Когда `СведенияОВнешнейОбработке()` всё-таки нужна

Только для НАСТОЯЩИХ внешних файлов `.erf`/`.epf`, загружаемых в справочник
`ДополнительныеОтчетыИОбработки`. Там она обязательна и возвращает структуру регистрации
(`Вид`, `Версия`, `Наименование`, `БезопасныйРежим`, `Информация`, `Команды` с
`Идентификатор`/`Использование`/`Модификатор`, для печатных форм — `Назначение`).

Терминологическая ловушка: в статьях и видео «внешняя печатная форма» часто означает именно
объект расширения по рецепту §3 — расширение ставится в пользовательском режиме и его объекты
обособлены, поэтому его называют «внешним». Никакой `СведенияОВнешнейОбработке()` там нет.

## 6. Разметка форматов в XML расширения (Конфигуратор-дамп)

Заимствованная подсистема:

```xml
<Subsystem uuid="<новый uuid>">
  <InternalInfo/>
  <Properties>
    <ObjectBelonging>Adopted</ObjectBelonging>
    <Name>ПодключаемыеОтчетыИОбработки</Name>
    <ExtendedConfigurationObject><uuid подсистемы в типовой></ExtendedConfigurationObject>
    <Content>
      <xr:Item xsi:type="xr:MDObjectRef">Report.ИмяОтчётаРасширения</xr:Item>
    </Content>
  </Properties>
  <ChildObjects/>
</Subsystem>
```

Объекты расширения перечисляются в `Content` **полным именем** (`Report.X`, `DataProcessor.Y`),
типовые — UUID'ом. Подсистему обязательно зарегистрировать в `Configuration.xml` → `ChildObjects`.
