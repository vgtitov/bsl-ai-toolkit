## [2.2.1] - 2026-07-31

### Changed
- **Границы `1c-dev` ↔ `1c-tester` по доступу к данным** — `1c-dev` больше не отправляет на
  `docs/data-access-architecture.md` напрямую (это документ дизайна, не инструкция), а явно
  указывает вызвать `1c-tester` за готовым воспроизводимым путём; `1c-tester` зеркально
  указывает, что не нужно копировать себе его рецепт. Причина: реальная сессия наткнулась на
  задачу доступа к данным через `1c-dev`, не нашла там прямой указки на уже существующий
  готовый рецепт `1c-tester` и потратила время на повторное открытие граблей, которые в этом
  рецепте уже были описаны.
- **`references/data-access-verification.md` (`1c-tester`)** — добавлены две грабли,
  обнаруженные в той же сессии и до этого нигде не задокументированные: (1) `scripts/onec_verify.py
  serve` держит процесс в переднем плане и должен запускаться агентом как фоновая задача, иначе
  таймаут; (2) фоновая обёртка на Windows/git-bash отчитывается «завершено» независимо от
  реального состояния процесса `ibsrv.exe` — готовность/остановка проверяются только через
  HTTP-порт и `Get-NetTCPConnection`, не через статус обёртки.

## [2.2.0] - 2026-07-30

### Added
- **Скилл `1c-tester`** — роль тестировщика/QA для 1С: какой уровень проверки нужен для изменения
  и как довести его до реального доказательства (вывод прогона, не ощущение), включая проверку
  доступа к данным живой ИБ (OData/HTTP-сервис расширения) для отладки или для AI.
- **`docs/data-access-verification-runbook.md`** — воспроизводимый путь проверки L2 (OData) / L3
  (`ai_debug`) на новой машине: автономный сервер, деплой расширения через SSH, диагностика по
  коду ответа, включая три обязательные поправки на кодировку (Basic-auth, кириллица в URL,
  JSON-тело) — устраняет ложный 401 от `curl -u` с кириллическим логином на Windows/git-bash.
- **`feat(remote)`**: команда `deploy-extension` в `designer_sync.py`.
- **Автономный сервер (`ibsrv`) как штатный слой** — проверен сквозняком на живой базе без
  веб-сервера и администратора; слой данных (OData/HTTP-сервис) работает и на файловой копии.
- **`switch_source.py`**: central-режим больше не теряет доступ к локальным клонам — при наличии
  реальных клонов в `ONEC_SRC_DIR` регистрируется дополнительный сервер `onec-code-local`.
- **`doctor.py`**: проверка регистрации COM-коннектора (`V83.COMConnector`) — ловит неполную
  регистрацию (CLSID есть, TypeLib — нет), которая роняет позднее связывание (PowerShell/.NET)
  ошибкой `TYPE_E_LIBNOTREGISTERED` без понятной причины.

### Fixed
- Обезличены оставшиеся упоминания заказчика/реальных имён баз, серверов и людей в toolkit.
- pre-push: Git LFS требуется только репозиториям с LFS, проверка вынесена и в `doctor.py`.

### Docs
- `1c-dev/SKILL.md`: явный триггер на задачи «нужны данные живой/файловой базы» — сначала
  `docs/data-access-architecture.md`/`docs/testing-ladder.md`, потом (если совсем не подошло) —
  импровизация вручную.

## [2.1.1] - 2026-07-29

### Fixed
- **Пин `mcp<2` в runtime-серверах и Docker.** v2.1.0 запинил только CI; сами серверы (`mcp/onec_mcp.py`,
  `onec_data_mcp.py`, `onec_ops_mcp.py`, `bsl_ls_mcp.py` — inline `dependencies`) и образы (`server/Dockerfile*`)
  тянули `mcp` без верхней границы, поэтому при свежей установке `uv run` ставил mcp 2.0.0 и падал на импорте
  `mcp.server.fastmcp`. Теперь везде `mcp>=1.2,<2` / `mcp<2`. Проверено: `uv run mcp/onec_mcp.py` поднимается.
- **Парсер `.env` (`load_dotenv_defaults`) съедал inline-комментарии в значение.** Строка вида
  `KEY=  # пояснение` давала значением `"# пояснение"`, а не пустоту, и `KEY=` (пусто) перетирало дефолт пустой
  строкой. Из-за этого локальный `.env` со строкой `ONEC_DATA_DEBUG_PATH=  # по умолчанию /hs/aidbg` ронял слой
  данных: `#` обрезал URL по фрагменту до `/base` → HTTP 404. Теперь загрузчик (обе копии — `onec_ops_mcp`,
  `onec_data_mcp`) срезает inline-комментарий у некавыченных значений и НЕ выставляет пустые (пусто = взять
  дефолт). `#` внутри кавычек сохраняется. Снимало ~21 «падение» тестов `onec_data` на машинах с локальным `.env`.

## [2.1.0] - 2026-07-29

### Added
- **`scripts/rds_setup.py` — настройка SSH-доступа к терминалу 1С для тех, кто с SSH не работал.** Одна команда на
  своей машине: проверка OpenSSH-клиента, генерация ключа `~/.ssh/onec_rds`, идемпотентная запись алиаса в
  `~/.ssh/config` (логин всегда в кавычках — иначе ssh калечит доменное имя на `\v`), печать публичного ключа и
  готового текста для администратора с обоими вариантами размещения ключа (обычная учётка → профиль, админская →
  `administrators_authorized_keys`). Подкоманда `check` — дружелюбная диагностика связи. Чистое ядро под тестами.
  Открывает batch-прогоны 1С (`onec_verify.py remote`) команде без ручной возни с SSH.
- **Точечный dump/load через SSH (`--host`) в `designer_sync.py`** — выгрузка/загрузка объектов конфигурации в
  пакетном режиме Конфигуратора на удалённом терминале рядом с кластером, тем же транспортом, что `onec_verify`.

### Fixed
- **bsl-ls: кириллица в пути ломала проверку синтаксиса** — из-за обрезки argv на Windows анализировался чужой
  модуль; мост теперь стартует из каталога проверяемого файла с `-s .`.
- **CI (tests.yml): пин `mcp<2`.** Релиз `mcp` 2.0.0 на PyPI убрал `mcp.server.fastmcp`, на который завязаны
  MCP-серверы, из-за чего непинованный `--with mcp` красил сборку. Держим `mcp` 1.x до отдельной миграции серверов
  на новый SDK (runtime-скрипты с inline `dependencies=["mcp"]` — отдельный хвост).

## [2.0.1] - 2026-07-24

### Fixed
- **Центральный `docker compose` не поднимался без тест-ИБ.** Сервис `onec-data` в v2.0.0 стал обязательным
  (`ONEC_DATA_BASE_URL:?` + `proxy depends_on onec-data`), из-за чего `compose up` падал везде, где слой данных не
  провизинен (центр на хосте, Work PC). Теперь `onec-data` — **opt-in через compose-профиль** `data`: дефолтный
  `compose up` поднимает `onec-code`/`onec-ops`/`proxy` (как раньше), а слой данных включается явно
  `docker compose --profile data up -d` при заданных `ONEC_DATA_*`. `ONEC_DATA_BASE_URL` смягчён с `:?` на `:-`,
  зависимость `proxy → onec-data` убрана (иначе compose поднимал бы сервис вопреки профилю).

## [2.0.0] - 2026-07-24

### Changed
- **Переименование `claude-1c-toolkit` → `bsl-ai-toolkit`** и переход на **AI-агностик** архитектуру: правила больше
  не привязаны к Claude Code. Единый источник `core/` (`AGENTS.md` + `skills/` + `mcp/servers.json`), из него
  `sh build.sh` генерирует конфиги под конкретных агентов. Старый корневой `CLAUDE.md` теперь генерируется как
  `@AGENTS.md` + Claude-специфика.

### Added
- Ядро `core/` (общее для всех AI-агентов): `AGENTS.md` (правила: спроси-инструмент, слои контура, гейт метаданных,
  производительность, безопасность), `core/skills/` (6 скиллов: `1c-dev` / `1c-analyst` / `1c-metadata` /
  `1c-admin-devops` / `1c-dba` / `1c-expert`), `core/mcp/servers.json` (профиль MCP).
- Мульти-агентность: `adapters/` (claude — эталон; codex/gemini — фолбэк; cursor/copilot/cline/windsurf/aider —
  rulesync/ручные) + `build.sh`. Оси переносимости: AGENTS.md + SKILL.md + MCP. Раздел про провайдеров LLM под РФ/санкции.
- Слой доступа к данным живой ИБ `onec-data` (MCP, 10 инструментов) + расширение 1С `ai_debug` (read-only под
  пользователем, честный RLS, маскирование ПДн, privileged за fail-closed-гейтом); локальный runner-EPF без SSH.
- OSS-обвязка: `CONTRIBUTING`, `CODE_OF_CONDUCT`, `SECURITY`, шаблоны Issue/PR, бейджи в README, CI (GitHub Actions),
  MIT `LICENSE`.
- Документация: `docs/CONCEPT.md` (методология, артефакты ЧТЗ/тех-проект, связь с курсами), `docs/TOOLS.md` (каталог
  инструментов), `docs/AGENT_SETUP.md` (настройка руками агента), `docs/ACCESS_SETUP.md` (доступ к LLM под санкциями),
  `docs/RELEASING.md` (процесс релизов), `docs/TEAM_MIGRATION.md` (миграция командного форка).
- Интеграция с 1C:EDT: `docs/EDT_SETUP.md` — опциональный MCP-плагин EDT (живой доступ к рабочему пространству), установка/подключение. Агенты Kiro и Roo Code добавлены в матрицу адаптеров.
- Кросс-платформенность: `build.ps1` (Windows-паритет `build.sh`), матрица ОС в README; `onboard.ps1` под новую структуру.
- Релизы: workflow `release.yml` (тег `vX.Y.Z` → GitHub Release + исходник расширения `ai_debug`); политика версий в `RELEASING.md`.

### Fixed
- CI: тесты падали в чистом окружении (`ModuleNotFoundError: lxml`) — в прогон добавлены зависимости движка
  `lxml`/`openpyxl`/`xlrd`, запуск изолирован (`--no-project`).

### Removed
- Устаревший личный `HANDOFF.md` из корня; служебная папка `docs/superpowers/` (спека перенесена в `docs/design/`).

### Added (слой применения и проверки, влито из onec-data)
- **Автономный сервер** (`onec_metadata/apply/standalone.py`) — HTTP-доступ к файловой базе (веб-клиент, OData,
  HTTP-сервисы) без веб-сервера и публикации администратором. Проверять слой данных можно сразу на файловой копии.
- **CLI лестницы тестирования** `scripts/onec_verify.py` — `check` (синтаксис платформой) и `smoke` (серверный BSL на
  реальных данных) одной командой, транспорт local или по `--host`.
- **Предполёт «защиты от опасных действий»** (`onec_metadata/apply/protection.py`) — ловит зависание батч-сеанса до
  подключения, локально по файлу настроек.
- **Готовность удалённого хоста** (`onec_metadata/apply/remote.py`) — проверки только на чтение перед прогоном на сервере.
- **Обработки и расширения** (`onec_metadata/apply/external.py`) — сборка/разбор `.epf`/`.erf` и `.cfe` через Конфигуратор.
- `docs/setup-actions-required.md` — что должен сделать человек (публикация, флаг защиты, платформа), со ссылками из инструментов.

### Существовало ранее (сводно)
- Движок правки метаданных `onec_metadata` (Конфигуратор-XML + EDT `.mdo`/`.dcs`, byte-perfect, round-trip verify,
  ~215 тестов) + CLI `bin/1c-meta`.
- MCP: `onec-code` (реальный код 1С), `bsl-ls` (диагностики BSL, в комплекте), `onec-ops` (эксплуатация: ТЖ/APDEX/
  Zabbix/Prometheus).
- Зашитые проверки: `bsl_guard.py` (межпроцедурный детектор «запрос в цикле»), гейты против поломки СКД и дрейфа свойств;
  git-хуки (commit-msg + pre-commit); лестница тестирования (docs/testing-ladder.md), `doctor.py` (health-check окружения).
