### Changed
- `mcp/onec_data_mcp.py`, маска ПДн (поведение меняется, колонки теперь маскируются точнее):
  - ссылка на сотрудника или физлицо (`Сотрудник`, `Физлицо`, `Работник` и ссылка с представлением в виде ФИО): представление и GUID скрываются, тип ссылки остаётся;
  - ФИО по значению: «Фамилия Имя Отчество», «Фамилия И.О.», «И.О. Фамилия» маскируются под любым именем колонки (в том числе алиасом) и внутри текста;
  - поля `оклад`, `зарплат*`, `заработн*` маскируются;
  - `Номер`, `НомерДокумента`, `КемВыдан`, `ДатаВыдачи` рядом с полем `Паспорт*` маскируются; паспорта РФ («4512 345678») и РБ («MP1234567») маскируются по значению;
  - `ИмяФайла`, `ИмяПоля`, `ИмяПараметра`, `ИмяОбъекта` и подобные технические поля больше не маскируются;
  - сообщения об ошибках сервера проходят ту же маску.
- Предел: «Фамилия Имя» без отчества и без инициалов, не в поле-ссылке на человека, а также ФИО строчными буквами по значению не распознаются. `ONEC_DATA_MASK_OFF=1` по-прежнему отключает маску целиком.

## [2.7.0] - 2026-10-28

### Added
- `scripts/depersonalize.py`: обезличивание текста, кода 1С (BSL), журналов, `.docx`, JSON и конфигов перед отправкой наружу (второе мнение другой модели, заявка Service Desk, письмо). Одиночный файл на stdlib. Заменяет ФИО, email, телефоны, УНП и ИНН, IP и адреса серверов, строки подключения 1С; токены и пароли не заменяет, а блокирует отправку (код 3, пустой stdout). Код не ломается: замены только в строках и комментариях, BOM и исходная кодировка (UTF-8, UTF-16, cp1251) сохраняются. Словарь имён и компаний только явный (`--dict`, `DEPERSONALIZE_DICT`, `--dict-auto`), карта соответствий только по `--map-out` (не перезаписывает, не пишет в синхронизируемые папки), режим каталога `--out-dir`. Облачные заглушки OneDrive дают понятный код 2. Описание и границы в `docs/DEPERSONALIZE.md`; без словаря фамилии без характерного окончания не ловятся. Проверен на реальной выгрузке конфигурации 1С и рабочих документах на Windows (Work PC), подробности в тестах `tests/test_depersonalize.py`.
- Границы: поддерживаются форматы РБ и РФ и международные телефоны, остальные страны добавляются конфигом позже; связка ФИО и должность отдельно не определяется; это снижение риска, а не анонимизация; документам с шаблонными примерами токенов нужна проверка человеком.

### Changed
- Адаптер Copilot (`copilot_adapter.py`) по умолчанию работает со скрытым окном у всех. Окно открывается само только до первого входа и при ошибке аутентификации (страница входа Microsoft ждёт логин или пароль: сразу; выбор учётки или MFA: примерно через полторы минуты вместо трёх), после входа вопрос повторяется скрыто. `--visible` или `AI_TOOLKIT_COPILOT_VISIBLE=1` показывает окно всегда, `AI_TOOLKIT_COPILOT_NO_LOGIN_WINDOW=1` не открывает его никогда. Раньше окно было видно всегда, а скрытый режим включали вручную переменной `AI_TOOLKIT_COPILOT_CMD` с `--headless` (по замечанию тестировщика на Windows).
- README описывает продукт; Ponytail, дисциплина и второе мнение вынесены в `docs/WORKFLOW_GUARDS.md`.

### Fixed
- `servicedesk.py`: готовый HTML в описании и заметках проходит белый список тегов (p, br, ul, ol, li, b, i, strong, em, div, a с http, https, mailto), скрипты, обработчики событий и `javascript:` экранируются; тесты на `update` (путь PUT, привязка решения к заявке, одноразовость).
- `servicedesk.py`: описание заявки и заметки уходили простым текстом, а SDP хранит их как HTML, поэтому переводы строк пропадали и нумерованные пункты сливались в одну строку. Теперь `create` и `note` превращают абзацы в `<p>`, строки в `<br>` и экранируют спецсимволы; готовый HTML не трогается. Тест `test_description_newlines_become_html_so_points_do_not_merge`.
- Второе мнение на Windows: вопрос, ответ Copilot, дифф и ответ Codex идут в UTF-8 байтами, независимо от локали и `PYTHONUTF8` (раньше при cp1251 вопрос доходил нечитаемым, а код выхода был 0). Пути вложений в команде Copilot на Windows экранируются правильно.
- `second_opinion.py status` называет причину, почему Copilot не настроен (нет входа, нет uv), и умеет живую пробу `status --probe` (вход и кодировка, ответ должен содержать слово из вопроса).
- В подсказке `designer_sync.py --contour` пример ключа базы заменён на нейтральный.
- `dev-workflow.md`: составной тип больше не помечен как «остаётся человеку» (правка делается `edit-type`).
- `onec-ops`: необязательные аргументы `zabbix_api_tool.params`, `zabbix_perf_report_tool.hosts` и
  `event_log_parse_tool.events` (по умолчанию `None`) объявлены как `dict`/`list` без `None` — схема MCP
  обещала `"default": null`, но явный `null` от клиента падал на валидации до вызова инструмента. Теперь
  тип `"dict | None"`/`"list | None"`.

## [2.1.1] - 2026-07-29

### Fixed
- **Пин `mcp<2` в runtime-серверах и Docker.** v2.1.0 запинил только CI; сами серверы (`mcp/onec_mcp.py`,
  `onec_data_mcp.py`, `onec_ops_mcp.py`, `bsl_ls_mcp.py` — inline `dependencies`) и образы (`server/Dockerfile*`)
  тянули `mcp` без верхней границы, поэтому при свежей установке `uv run` ставил mcp 2.0.0 и падал на импорте
  `mcp.server.fastmcp`. Теперь везде `mcp>=1.2,<2` / `mcp<2`. Проверено: `uv run mcp/onec_mcp.py` поднимается.
- **Парсер `.env` (`load_dotenv_defaults`) съедал inline-комментарии в значение.** Строка вида
  `KEY=  # пояснение` давала значением `"# пояснение"`, а не пустоту, и `KEY=` (пусто) перетирало дефолт пустой
  строкой. Из-за этого локальный `.env` со строкой `ONEC_DATA_DEBUG_PATH=  # по умолчанию /hs/aidbg` ронял слой
  данных: `#` обрезал URL по фрагменту до `/base` → HTTP 404. Теперь загрузчик (обе копии — `onec_ops_mcp`,
  `onec_data_mcp`) срезает inline-комментарий у некавыченных значений и НЕ выставляет пустые (пусто = взять
  дефолт). `#` внутри кавычек сохраняется. Снимало ~21 «падение» тестов `onec_data` на машинах с локальным `.env`.

## [2.0.1] - 2026-07-24

### Fixed
- **Центральный `docker compose` не поднимался без тест-ИБ.** Сервис `onec-data` в v2.0.0 стал обязательным

  зависимость `proxy → onec-data` убрана (иначе compose поднимал бы сервис вопреки профилю).
