# onec_metadata — задачи на дальнейшие улучшения

Приоритезированный бэклог. Инвариант для КАЖДОЙ задачи (не повторяется в пунктах):
TDD (сначала падающий тест), byte-perfect минимальный дифф, оба формата
(Конфигуратор + EDT) где применимо, обезличенные фикстуры из реальной структуры,
применение только в ТЕСТ-базу + round-trip, adversarial-ревью перед merge.

## P1 — Редактирование существующего (главный пробел)

Сейчас операции почти все на ДОБАВЛЕНИЕ; правка существующего — только текст
запроса СКД и значение права. Это закрывает основной разрыв.

- [x] **`set-property`** ✅ — изменить скалярное свойство существующего объекта или
  реквизита по адресу (объект → [реквизит] → свойство → значение): синоним,
  комментарий, флаг (`Indexing`/`Индексирование`, `FullTextSearch`, `PasswordMode`,
  `Use`/`Использование` и т.п.). Приёмка: значение меняется, соседние узлы не
  тронуты, идемпотентно, оба формата.
- [x] **`edit-type`** ✅ — сменить/расширить тип существующего реквизита: длина/
  точность строки/числа (квалификаторы), составной тип (несколько `Type`),
  ссылка. Приёмка: корректная перестройка блока `Type` + квалификаторов.
- [x] **`edit-type` — обобщение узлов + тип с нуля** ✅ 2026-07-15 — адресация по имени
  `Attribute/Dimension/Resource/AddressingAttribute` и объект-уровень (`--member` опущен:
  `SessionParameter/Constant/DefinedType`); сборка блока `Type`/`type` и квалификатора
  (`--length` строка, `--precision`/`--scale` число) С НУЛЯ на бестиповом поле; оба формата,
  byte-perfect. Тесты: register (изм./рес.), sessionparameter/constant, untyped.
- [x] **`edit-type` — составной тип** ✅ 2026-07-15 — несколько типов в поле: `type_ref` списком
  (CLI: повторить `--type`); N `v8:Type`/`types` byte-perfect (общий `_ensure_types`), квалификаторы
  к составному запрещены, из составного обратно в одиночный сворачивается. Оба формата. Тесты `test_composite_*`.
- [ ] **`rename` ИДЕНТИФИКАТОРА (имя объекта/реквизита/процедуры)** — РИСКОВАННО: ломает ссылки,
  одинаковые имена бывают у РАЗНЫХ объектов с разным назначением. НЕ переименовывать «в лоб» всё
  найденное. Только с анализом внешних ссылок и КОНТРОЛЕМ ЧЕЛОВЕКА (каскад с починкой ссылок и
  preview→confirm уже делает `edt-mcp`; здесь — если и добавлять, то с той же гарантией).
- [x] **Правка ПРЕЗЕНТАЦИИ (безопасно, ссылок не ломает)** — ✅ 2026-07-15 `set-synonym`:
  Синоним/«Наименование» существующего языка у реквизита/измерения/ресурса (`--member`) или самого
  объекта; оба формата, свободный текст, byte-perfect. Comment уже покрыт `set-property`. Тест `test_set_synonym`.
  Остаётся: добавление НОВОГО языка в синоним; заголовок элемента формы (`form add-field --title`).

## P3 — Создание объектов с нуля

- [x] **Создание реквизита без образца — через ДОНОР** ✅ (`add_child --donor`):
  образец берётся из однотипного объекта конфигурации + регенерация id (версия-
  корректно). Донор — корневой уровень, элементы с порождаемым типом (ТЧ) не
  поддержаны. Пустой ChildObjects (совсем нет детей) — ещё отдельная операция.

- [ ] **HTTP-метод как вид `add_child`** (дитя URLTemplate; в EDT — вложенный
  `<methods>`, подтверждено выгрузкой ERP; в Конфигураторе — `Method`).

- [ ] **Новый объект целиком / копия типового объекта в расширении** —
  операция `object copy`/`object add`/`object delete` (сейчас ручная правка XML:
  `ObjectBelonging=Native`, свежие uuid + InternalInfo, регистрация в манифесте,
  вложенные подсистемы, `totalField` в СКД). Спека, уроки и версионные различия —
  `docs/create-object-in-extension.md`. **Роль (Role)** — тоже вид объекта
  (2026-08-20): без `InternalInfo`/`xr:GeneratedType`, права в отдельном
  `Rights.xml` (`http://v8.1c.ru/8.2/roles`), а назначение роли пользователю —
  ДАННЫЕ ИБ, не конфигурация (§1.10). Покрыть `object add` для Role +
  `role grant` на собственный объект расширения по имени.

  `ПравоДоступа`/формирования под обычной учёткой через смоук-раннер ЗАВИСАЕТ на

  (проверено в бою): (а) UI-проверка веб-клиентом; (б) grep по `Roles/*/Ext/Rights.xml`
  на вопрос «есть ли право у какой-либо роли» (прямого API «права роли на объект» нет);
  (в) назначение роли смоуком под полными правами + UI-подтверждение. Оформить как

  `apply/permissions`).
- [ ] **Визуальная проверка под пользователем** (2026-08-21) — смоук подтверждает
  КОМПОНОВКУ, но НЕ то, что видит человек: таблица отчёта в веб-клиенте = Canvas (не
  сериализуется в `inner_text`), а программная компоновка идёт ДРУГИМ путём, чем форма.
  Нужна отдельная ступень-гейт для доработок отчётов/форм: визуальный прогон под
  обычной учёткой (веб-клиент + тонкий/толстый клиент через управление приложением),
  с отбором по малому объёму данных и ожиданием ПОЛНОГО завершения формирования
  (скриншот снимать после исчезновения индикатора «формируется…»).
- [ ] **Урок `.Настройки` vs `.ПолучитьНастройки()`** (2026-08-21) —
  `КомпоновщикНастроек.ПолучитьНастройки()` возвращает КОПИЮ настроек; программная
  модификация (добавление полей в глобальный Выбор) работает только через СВОЙСТВО
  `.Настройки`. Зафиксировать в рецепте «программная доработка вывода отчёта».
  Связанный факт: XML-тег `<dcsset:choice>` (глобальный Выбор в СКД-макете) платформа
  не приняла (XDTO-ошибка), точный формат сериализации `НастройкиКомпоновкиДанных`
  штатными средствами не получен — обход через `ObjectModule.bsl` надёжнее.
- [ ] **Реквизит на ТИПОВУЮ форму — через `&После` на общий модуль, НЕ копия формы** (2026-08-21) —
  полная копия `Ext/Form.xml` типовой формы в расширении НЕ грузится: «Неверный путь к данным /
  Неверное имя команды» — не резолвятся ссылки на тип каталога (`cfg:CatalogObject.*`), общие
  команды (`CommonCommand.*`), события формы. Правильный способ — заимствовать ОБЩИЙ модуль БСП
  `СобытияФорм...` (вызываемый из `ПриСозданииНаСервере` формы) и в расширении добавить
  `&После("<Процедура>")` + `Ав_<Процедура>(...) Экспорт`, где по `Форма.ИмяФормы` программно
  `Форма.Элементы.Добавить(...)`. Прецедент в самом `Ав_Доработки`: `ПользователиПереопределяемый`
  + `&После("ПриОпределенииНазначенияРолей")`. Директива `&Вместо` ЗАТИРАЕТ типовую логику процедуры.
- [ ] **`ObjectBelonging` в расширении (уточнение к create-object-in-extension)** (2026-08-21) —
  новый объект/реквизит = `Native` (НЕ сериализуется в дампе; `Added`/`Own` платформа отвергает
  «Неверное значение перечисления»). Заимствованный объект = `Adopted`; для маппинга по UUID при
  `KeepMappingToExtendedConfigurationObjectsByIDs=true` — `<ExtendedConfigurationObject>UUID_типового</…>`.
- [ ] **Регистрация отчёта расширения в окне «Отчеты» (все отчёты)** (2026-08-21) — отчёт из
  расширения НЕ появляется в «Отчеты» только от подсистемы; нужна БСП-регистрация через

  `Вид=ДополнительныйОтчет`, команда с `ТипКомандыОткрытиеФормы()`). Альтернатива — флаг расширения
  «Использовать роли по умолчанию для всех пользователей».
